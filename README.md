# Atelier Gương

## Run locally

1. Install dependencies with `npm install`.
2. Create the `AtelierGuong` database in SQL Server (or choose an existing database).
3. Run `schema.sql` against it in SQL Server Management Studio or Azure Data Studio.
4. Create a SQL login/database user with the minimum permissions needed by the site: read/insert/update/delete categories; read, insert, update, and deactivate products; update product `Stock` and `SoldCount`; read/insert/update customers including `IsActive`; read/insert/update/delete customer addresses; read/insert/update orders and order items; insert order status history; read/insert/update/deactivate coupons; and read/insert/update/delete employees.
5. Copy `.env.example` to `.env`, enter the SQL connection settings, replace `AUTH_TOKEN_SECRET` with a randomly generated secret of at least 32 bytes, and set a unique `ADMIN_USERNAME` and strong `ADMIN_PASSWORD`. Set `COOKIE_SECURE=true` behind HTTPS. Keep `.env` private; it is ignored by Git.
6. Start the site with `npm start`, then open `http://localhost:3000`.

For a local SQL Server Express named instance such as `.\SQLEXPRESS`, either configure a fixed TCP port (for example `SQL_SERVER=localhost`, `SQL_PORT=1433`, and leave `SQL_INSTANCE` empty), or set `SQL_INSTANCE=SQLEXPRESS` and make sure SQL Server Browser is running so the instance can be resolved. When `SQL_INSTANCE` is set, the app ignores `SQL_PORT`. Create the `AtelierGuong` database first, then select it in SQL Server Management Studio before running `schema.sql`. Do not run the schema while the selected database is `master`.

Product search, filters, sorting, and pagination are queried by the `/api/products` endpoint from `dbo.Products`. Search uses parameterized SQL across product name, SKU, category, mirror type, brand, and description. The browser does not fall back to its demo catalog if SQL Server is unavailable.

The product API accepts `q`, repeated `category`, `shape`, `space`, and `price` query parameters, plus `sort`, `page`, and `pageSize`. Price band values are `under-500`, `500-1000`, `1000-2000`, `2000-5000`, and `over-5000`. Sort keys are `featured`, `price-asc`, `price-desc`, `name-asc`, `name-desc`, `newest`, and `best-selling`. `newest` uses `CreatedAt`; `best-selling` uses `SoldCount`.

The admin back office is available at `/admin`. It uses a separate HTTP-only session cookie and requires `ADMIN_USERNAME`, `ADMIN_PASSWORD`, and `AUTH_TOKEN_SECRET` to be configured. The dashboard and statistics view read live SQL counts, revenue, daily/monthly/yearly totals, and top-selling products; cancelled orders are excluded from revenue. Product, category, order, customer, employee, and coupon management use protected `/api/admin` endpoints. Category changes cascade to linked products; a category cannot be deleted while products use it. Cancelling an order restores inventory and coupon usage; reopening a cancelled order rechecks stock and coupon capacity. Customer details show their recent purchase history; locked customers cannot log in. Employee records include code, contact details, position, salary, hire date, and employment status. Coupon codes are checked server-side and applied atomically when an account customer places an order; uploaded JPG, PNG, and WebP product images are limited to 5 MB and stored under `uploads/products`. Persist that directory when deploying the app.

The schema includes material, shape, size, finish/color, use case, cleaning and warranty text, a JSON image gallery, creation date, sales count, customer accounts, employee records, saved addresses, coupons, coupon snapshots on orders, SQL order history, status events, and product reviews. Customer orders show a fulfillment timeline from `Chờ xác nhận` through `Đã giao`, with `Đã hủy` displayed separately. A customer can leave one 1–5-star review per purchased order item; the API checks ownership and prevents duplicate reviews. Orders capture city, district, ward, detailed address, note, and `cod`, `bank`, or `online` payment selection. SQL order numbers use `HD` plus the order identity padded to five digits; guest demo orders use a browser-local sequence. Online selection is recorded as pending payment; no payment gateway is configured. The script adds missing columns and creates missing account, employee, coupon, and order tables when rerun. Cart discounts are calculated from `OldPrice` and `Price`; shipping is 100,000 VND. If SQL Server is not configured or reachable, account and catalog APIs return an error instead of silently using sample data.
